# 用户登录与旅行会话隔离设计

## 1. 背景与目标

当前系统使用全局唯一 `session_id` 管理旅行规划状态、任务、草稿和版本，但没有用户模型、认证机制或资源所有权校验。任何调用方只要知道资源 ID，就可以读取或操作对应数据。

本次改造的目标是：

- 提供用户名/密码注册和登录。
- 使用单个有效期 7 天的 JWT 访问受保护接口。
- 每个旅行会话和异步任务明确归属于一个用户。
- 用户只能访问、统计和删除自己的资源。
- 保留历史无归属数据，但不向任何登录用户暴露。
- 新增旅行会话级联硬删除。

本次不实现 Refresh Token、服务端 Token 黑名单、管理员、角色权限、修改密码、找回密码、用户删除、邮箱或第三方登录。

## 2. 已确认的产品决策

- 登录方式：用户名和密码。
- 用户名：去除首尾空格并转为小写后保存；长度 3～32，只允许英文字母、数字和下划线；不区分大小写且全局唯一。
- 密码：长度 8～72；数据库只保存 Argon2id 哈希。
- Token：单个 HS256 JWT，有效期 7 天，不续期、不保存到服务端。
- 退出登录：前端删除 Token；已复制的 Token 在过期前仍然有效。
- Token 传输：`Authorization: Bearer <token>`；SSE 由前端使用支持自定义请求头的 `fetch` 流式读取。
- 注册成功后立即返回 Token，无需再次登录。
- 账号接口只包含注册、登录和查询当前用户。
- 所有旅行相关接口必须登录。
- 数据库只支持 MySQL；正式应用在其他数据库模式下启动失败。
- 历史会话和任务的 `user_id` 保持 `NULL`，任何登录用户都不可访问。
- 删除会话时永久删除关联任务、事件、草稿和版本，不提供恢复。

## 3. 总体架构

新增独立 `app/auth` 包，认证逻辑不进入现有编排器或 `main.py`：

```text
app/auth/
├── models.py         用户领域模型
├── schemas.py        注册、登录、Token、当前用户 DTO
├── security.py       Argon2id 哈希和 JWT 编解码
├── service.py        注册与登录业务规则
├── dependencies.py   FastAPI 当前用户依赖
└── router.py         /api/auth 路由
```

认证组件依赖一个 MySQL 用户 Store。路由通过 `get_current_user` 解析 Bearer Token，并把不可伪造的 `user_id` 传入旅行会话、任务、草稿、版本和统计 Store。请求体、路径参数和查询参数都不能指定或覆盖所有者。

现有 `main.py` 只负责注册认证 Router，并给现有旅行相关路由增加当前用户依赖。本次不拆分其他既有路由，避免无关重构。

## 4. 数据模型

### 4.1 users

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `user_id` | `CHAR(36)` | 主键 | 服务端生成的 UUID |
| `username` | `VARCHAR(32)` | 非空、唯一 | 已转为小写的规范化用户名 |
| `password_hash` | `VARCHAR(255)` | 非空 | Argon2id 哈希，不保存明文 |
| `created_at` | `DATETIME(6)` | 非空 | UTC 创建时间 |

建立唯一约束 `uq_users_username`。用户名预检查只用于友好错误；唯一约束负责处理并发注册竞争。

### 4.2 资源所有权

`agent_sessions` 新增可空 `user_id`，外键指向 `users.user_id`。建立 `(user_id, updated_at)` 和 `(user_id, status, updated_at)` 索引，用于当前用户的会话列表和筛选。

`trip_planning_tasks` 新增可空 `user_id`，外键指向 `users.user_id`。建立 `(user_id, created_at)` 和 `(user_id, status, created_at)` 索引。

列在数据库层保持可空是为了兼容历史数据；应用层要求所有新会话和新任务必须具有用户 ID。`AgentState` 和 `TripPlanningTask` 同步保存 `user_id`，确保检查点、Worker 恢复和故障报告不丢失所有权。

草稿、版本通过 `session_id` 继承会话所有权，任务事件通过 `task_id` 继承任务所有权，不重复保存 `user_id`。任何子资源操作都必须先用当前用户查询父资源。

### 4.3 防止删除后被 Worker 重建

现有会话 Store 的 UPSERT 同时承担首次创建和检查点更新。为避免运行中的旧 Worker 在会话删除后通过 UPSERT 重建数据，需要拆成两种语义：

- `create_state`：只允许首次插入，重复 ID 冲突。
- `save_state`：只更新已存在且属于同一用户的会话；目标不存在时失败，不能重新插入。

Worker 从任务携带的 `user_id` 加载和更新会话。会话被删除后，后续心跳、检查点和终态写入都必须表现为租约丢失或资源不存在，不能恢复已删除记录。

## 5. JWT 与密码安全

新增配置：

| 配置 | 默认值 | 规则 |
|---|---|---|
| `JWT_SECRET_KEY` | 无 | 必填，去除空格后至少 32 个字符 |
| `JWT_ALGORITHM` | `HS256` | 首期只接受 `HS256` |
| `JWT_EXPIRE_DAYS` | `7` | 必须为正整数 |

JWT Claims：

| Claim | 含义 |
|---|---|
| `sub` | 用户 UUID，是授权判断的唯一身份来源 |
| `iat` | UTC 签发时间 |
| `exp` | UTC 过期时间，默认为签发后 7 天 |
| `typ` | 固定为 `access`，防止未来其他 Token 类型混用 |

JWT 不包含密码哈希或其他敏感数据。缺失、畸形、签名无效、用户不存在、`typ` 错误和过期统一视为未认证。

密码使用 Argon2id 哈希与校验。密码明文、哈希和完整 JWT 禁止进入应用日志、异常文本、验收录制和 API 响应。

## 6. 认证接口

### 6.1 POST /api/auth/register

请求字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 规范化后长度 3～32，只允许字母、数字和下划线 |
| `password` | string | 是 | 长度 8～72 |

成功返回 `201 Created`：

| 字段 | 类型 | 说明 | 枚举值 |
|---|---|---|---|
| `access_token` | string | 7 天有效的 JWT | 无 |
| `token_type` | string | Authorization Scheme | 固定为 `bearer` |
| `expires_in` | integer | Token 有效秒数 | 默认 `604800` |
| `user` | object | 当前用户 | 见 UserResponse |

用户名已存在返回 `409 Conflict`。请求格式错误返回 `422 Unprocessable Entity`。

### 6.2 POST /api/auth/login

请求字段与注册接口一致。成功返回 `200 OK`，响应结构与注册接口相同。用户名或密码错误统一返回 `401 Unauthorized`，不得区分账号不存在和密码错误。

### 6.3 GET /api/auth/me

要求 Bearer Token。成功返回 `200 OK`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | 用户 UUID |
| `username` | string | 规范化用户名 |
| `created_at` | string | ISO 8601 UTC 创建时间 |

认证失败返回 `401 Unauthorized`，并设置 `WWW-Authenticate: Bearer`。

## 7. 旅行接口权限与数据流

以下资源必须根据当前用户隔离：

- 同步旅行规划。
- 异步任务创建、查询、取消和 SSE 事件。
- 会话列表、详情、执行视图和恢复。
- 草稿创建、读取、更新、评估和确认。
- 行程版本列表与详情。
- 执行基线、质量基线和依赖会话数据的验收统计。
- 景点图片和工具白名单查询。

认证成功后：

1. 同步规划把当前 `user_id` 写入新的 `AgentState`。
2. 异步规划把同一 `user_id` 写入任务和对应会话。
3. Store 查询必须使用 `user_id + resource_id`，不得先按资源 ID 读取后再在路由层过滤。
4. 用户访问其他用户、历史无归属或不存在的资源时统一返回 `404 Not Found`，避免泄露资源存在性。
5. 会话列表和所有统计查询必须在数据库查询阶段增加 `user_id` 条件。
6. Worker 使用任务中持久化的 `user_id` 恢复会话，不从外部请求推断所有者。

面向业务客户端的公开接口仅包括注册、登录和健康检查。`/api/auth/me` 及上述旅行相关接口必须登录。Prometheus 和 Redis 运维接口保持现有部署访问策略，不纳入本次用户会话体系，也不因业务 JWT 自动变为公开接口。

## 8. Redis 与缓存隔离

执行视图和任务进度属于用户数据，对应缓存键必须包含 `user_id`。即使缓存命中，也只能通过当前用户对应的键读取。

高德路线、天气、景点、酒店和餐厅属于公共 Provider 数据，继续跨用户共享缓存，不增加用户维度。

SSE 接口在开始流式响应前校验任务所有权。后续断线恢复仍使用 `Last-Event-ID` 或 `after_event_id`，但 Token 只能通过 Authorization Header 传递，禁止放入 URL 查询参数。

## 9. 会话级联删除

新增 `DELETE /api/trip/sessions/{session_id}`：

- 仅允许所有者删除。
- 成功返回 `204 No Content`，无响应体。
- 不存在、无归属或属于其他用户时返回 `404 Not Found`。
- 在一个 MySQL 事务中删除任务事件、任务、草稿、版本和主会话。
- 删除运行中任务时先使现有租约和写入资格失效；旧 Worker 不得重新创建会话或写入终态。
- 数据库提交成功后，清理对应执行视图和任务进度 Redis 缓存。
- 路线、天气等共享 Provider 缓存不删除。

## 10. 错误语义

| HTTP 状态 | 场景 |
|---|---|
| `201` | 注册并签发 Token 成功 |
| `200` | 登录、查询当前用户或其他读取成功 |
| `204` | 会话级联删除成功 |
| `401` | 登录失败，或 JWT 缺失、无效、过期 |
| `404` | 当前用户看不到目标资源，包括其他用户资源 |
| `409` | 用户名冲突或数据库唯一约束竞争 |
| `422` | 请求字段格式或长度校验失败 |
| `503` | MySQL 等关键持久化依赖不可用 |

错误响应沿用 FastAPI 的 `detail` 字段。认证错误信息不包含用户名存在性、JWT 内容、密码或内部异常细节。

## 11. MySQL-only 启动与迁移

正式应用启动时检查：

- `DATABASE_BACKEND=mysql`。
- `JWT_SECRET_KEY` 存在且满足长度要求。
- JWT 配置有效。

不满足时立即终止启动并输出明确但不包含密钥内容的配置错误。

新增 Alembic 迁移创建 `users` 表，并给会话、任务增加所有权字段、外键和索引。迁移不回填历史所有权。SQLite 实现仅保留给既有单元测试和 SQLite→MySQL 数据迁移工具，不再作为正式应用后端。

GitHub Actions 增加 MySQL 服务与测试环境变量，认证和主应用集成测试使用真实 MySQL。

## 12. 测试与验收标准

必须覆盖：

- 用户名规范化、格式、长度和大小写唯一性。
- 并发注册时唯一约束冲突稳定映射为 409。
- 密码哈希与验证，数据库中不存在明文密码。
- JWT 正常签发、过期、签名错误、错误类型和畸形输入。
- 注册、登录和 `/me` 的成功与错误响应。
- 用户 A 无法列表、读取、恢复、编辑、取消、监听或删除用户 B 的资源。
- 同步规划和异步任务都正确写入用户 ID。
- Redis 命中不能绕过所有权校验。
- 用户统计只包含当前用户的数据。
- 历史 `user_id IS NULL` 数据存在但对所有用户不可见。
- 会话删除永久清除任务事件、任务、草稿和版本。
- 删除运行中会话后，旧 Worker 无法重新写入或重建会话。
- `DATABASE_BACKEND` 非 MySQL 或 JWT 配置无效时应用启动失败。
- 现有确定性质量门继续通过。

验收完成的定义：两个已注册用户可以分别创建旅行规划；双方的列表和统计互不包含对方数据；猜测对方资源 ID 只能得到 404；删除自己的会话后所有关联数据均不可访问，后台 Worker 也不能恢复该会话。
